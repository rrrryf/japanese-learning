# 用 Cursor 继续优化：任务清单 + 沟通话术

> 上一轮已经修了 18 项（P0 崩溃 / P1 数据质量 / P2 性能 / P3 工程化）。
> 这份文档是**剩下的活**和**怎么让 Cursor 高效干活**。

---

## 一、每次开新对话，先说这句

```
先读 .cursor/rules/ 下四份规则和 docs/CURSOR-TASKS.md，读完用三句话复述：
你在改哪个副本、这个项目的禁区是什么、改完要跑什么验证。复述完等我确认再动手。
```

**为什么**：Cursor 默认会直接改代码。让它先复述，你能立刻看出它有没有读进去
（比如它说"改私有版"就说明它没看清路径）。

## 二、提任务的方式

### 坏例子

```
帮我优化一下这个项目的代码和功能
```

结果：它会重构目录、加类型标注、提议引入 React、把 `app.js` 拆成模块——
全是你不想要的。

### 好例子

```
任务：给 examples 表的例句查询加索引，解决 instr() 全表扫描。

背景：_fetch_examples 用 instr(jpn, ?) 匹配，无索引，每次全表扫 3.2 万行。
实测查「食べる」例句约 30ms，占总响应时间一半。

要求：
1. 只改 web/lookup.py 和 build_db.py，不要动路由和其他函数
2. 加 index 后要做迁移（已有库要能平滑升级，参考 migrate_add_index.py 的写法）
3. 验证：查 10 个常见词的 /api/word，中位耗时要低于 12ms，把前后对比贴给我
4. 跑 tests/test_units.py 和 .\run_tests.ps1，0 fail 才算完成

不要做的事：不要重构 _fetch_examples 的签名，不要改返回结构。
```

差别在哪：**给出具体文件、具体指标、明确的"不要做"**。

## 三、四个提高成功率的习惯

### 1. 一次只给一个任务

Composer 模式下它能一次改 10 个文件，但一次给它 5 个任务，它会在任务之间互相干扰
（改 A 的时候顺手动 B 的接口）。**做完一个、跑测试、确认、再下一个。**

### 2. 让它自己跑测试，把输出贴出来

```
改完自己跑：
  $env:PYTHONIOENCODING='utf-8'; python tests/test_units.py
  .\run_tests.ps1
把最后的汇总行贴给我，不要只说"测试通过"。
```

它会撒谎说"已通过"。要它贴原始输出。

### 3. 用数字验收，不用"更好"验收

| 别说 | 说 |
|---|---|
| 让搜索更快 | `食べる` 的 p50 从 76ms 降到 30ms 以内 |
| 优化排序 | 搜「吃」时 `食べる` 必须在前 2 |
| 改进错误处理 | 传 10³⁰ 返回 422 而不是 500 |

### 4. 明确禁止顺手重构

```
范围限制：只改我提到的函数。其他文件不要动，不要加类型标注，
不要重命名变量，不要格式化整个文件。如果发现别的问题，写在回复末尾的
「发现的其它问题」里，不要直接改。
```

## 四、剩余任务清单

按性价比排序。每项都写了验收标准，可以直接复制给 Cursor。

### T1 · 例句查询加索引（性能，最值得做）

**问题**：`_fetch_examples` 用 `instr(jpn, ?)`，3.2 万行全表扫。

**做法选项**：
- A. 建 FTS5 虚拟表（`examples_fts`），查询走全文索引 → 最快，但要改查询逻辑
- B. 给 `jpn` 加前缀索引——`instr` 用不上，只能改成 `LIKE 'x%'`，会漏中间匹配
- C. 预处理：导出时额外存一份"句首 3 字"的映射表

推荐 A。注意 `build_db.py` 建表 + `setup_data.py` 导入都要改，还要写迁移。

**验收**：查 10 个常见词的 `/api/word`，例句部分耗时 < 12ms；`tests/test_units.py` 0 fail。

---

### T2 · 语法接续（connection）中文化

**现状**：100 条语法的接续是英文 `Clause A + が + Clause B`，前端已加「英文」标注。
中文释义（`explain_zh`）已补完 100/100。

**做法**：照 `scripts/fill_gloss_zh.py` 的套路写 `scripts/fill_grammar_conn.py`，
或用规则翻译（`Clause` → `从句`、`Verb-stem` → `动词词干`、`Noun` → `名词`）。
规则翻译更快更稳，100 条里有 80 条是固定模式。

**验收**：`grammar` 表加 `connection_zh` 列，100 条全有；前端接续区优先显示中文。

---

### T3 · 刷新页面丢失面板状态

**现状**：在 `#/exam/<id>` 做到第 5 题，按 F5 回到第 1 题；筛选条件、滚动位置都丢。

**做法**：把 `examLevel` / `examDrillSubject` / 当前题号写进 `sessionStorage`，
初始化时读回。注意别把答题进度也存（那属于练习题日志，已经存了）。

**验收**：做到第 5 题刷新，仍在第 5 题且选项保留；等级下拉不重置。

---

### T4 · 私有版单元测试适配

**现状**：私有版没有 `mock_exam.py`（走 在线题库 API），直接复制 `test_units.py` 会
`ModuleNotFoundError`。

**做法**：私有版那份改成只测 `conjugator` + `weakness`，`mock_exam` 相关用例用
`try: import mock_exam / except ImportError: skip` 包起来。

**验收**：两版各自 `python tests/test_units.py` 都能 0 fail。

---

### T5 · 搜索排序彻底解决（需要数据）

**现状**：搜「吃」第一条是麻将用语 `チー`（「吃」在 JMdict 里确实是独立词条，
精确匹配优先），`食べる` 排第 2。

**根治需要词频**。可选来源：
- `data/jlpt_words` 的等级（已有，已用于排序）
- 新闻语料词频表（如 BCCWJ 词频，需确认许可）
- 例句表里该词出现的次数（现成数据，免费）

**最省事的做法**：用 `examples` 表统计每个词形出现次数，当作频次权重。
出现多的排前面。不需要外部数据。

**验收**：搜「吃」「漂亮」「おいしい」，第 1 条都是 JLPT N5–N3 的常见词。

---

### T6 · 移动端布局

**现状**：只在 1280px 宽验证过。手机上 `exam-drill-chips` 会换行、
`.ld-section` 的 padding 偏大。

**做法**：加 `@media (max-width: 640px)`，重点看三页：查词详情、模考答题、语法列表。

**验收**：375px 宽（iPhone SE）下三个页面无横向滚动、按钮可点。

---

### T7 · 数据导出与备份

**现状**：练习日志在 `web/cache/exam-logs/`，换机器就丢。

**做法**：加 `/api/export`（打包练习日志 + 生词本为 zip）和 `/api/import-backup`。
或者更简单：在前端加个「导出我的记录」按钮，下载 JSON。

**验收**：导出再导入，薄弱点统计数字一致。

---

### T8 · 语法条目扩容

**现状**：只有 100 条（N5–N1 各 20）。真实 JLPT 语法点约 500+。

**注意**：`data/openjlpt_grammar_*.json` 每级只有 20 条，要扩得先找数据源。
不要用 LLM 编语法条目——语法解释错了比没有更糟。

**验收**：新增条目带来源标注；`tests/test_units.py` 的答案分布检查仍通过。

## 五、给 Cursor 的"不要碰"清单

复制这段话到对话开头，能省掉一半返工：

```
不要碰的地方：
1. jmdict.db / JMdict_e.xml / JMdict_e.gz —— 大文件，已在 .gitignore
2. web/cache/imported_exams/ —— 可能是付费内容，只在本地
3. idx_word_forms_seq 索引 —— 性能命脉
4. web/static/ 的架构 —— 不加构建步骤、不拆模块、不引入框架
5. _normalize 的答案校验 —— 数据质量护栏，不要放宽
6. 已有测试的断言 —— 如果测试失败，先怀疑代码而不是改测试
```

## 六、什么时候该自己看代码

Cursor 在下面这几种情况下容易给你错的东西，建议先自己确认：

| 情况 | 为什么 |
|---|---|
| 涉及两个副本的改动 | 它分不清 8765/8766，可能改错副本 |
| 数据许可问题 | 它会告诉你"CC-BY 可以随便用"，实际有 share-alike 义务 |
| 性能数字 | 它常把"加了个索引"当成"变快了"，要它贴实测 |
| 大范围重构 | 这项目故意保持单文件 SPA，它很容易"帮你规范" |
